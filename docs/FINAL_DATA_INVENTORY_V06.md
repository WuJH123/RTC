# Final data inventory — RTC v0.6

This inventory defines the minimum authoritative data/evidence set for the final Wuhan sparse-sensing → differentiable-world-model → TFV-first MPC study.

## 1. Reusable scientific inputs

These are inputs, not historical RTC-derived results:

1. Frozen physical/event SWMM INPs for the selected rainfall events.
2. `data/priority_nodes.txt`, exactly eight verified PFV_CORE8 nodes.
3. Frozen sparse-sensor node list.
4. New rainfall/event registry containing `event_id`, `rainfall_group`, `inp_path`, `scientific_split`, `development_fold`, plus rainfall descriptors when available.
5. Static actuator/network information encoded by the frozen INP.

They may be reused only if their hashes remain unchanged.

## 2. Fresh Workspace contract

Every RTC-derived artifact must be regenerated under one empty Fresh Workspace after the final source tree is frozen.

Required root artifact:

```text
FRESH_WORKSPACE_MANIFEST.json
contracts/event_registry_with_splits.csv
contracts/rainfall_design_evidence.json
preflight/inp_audit.json
```

The public training pipeline rejects branch metadata outside the workspace and rejects artifacts generated by a different RTC source tree.

## 3. Phase-0 timing pilot data

Purpose: determine the production observation/model step, control update, history and prediction horizon before large production data generation.

Generate development-only high-frequency data:

```text
phase0/d0/...                         No-supervisory-RTC trajectories, <=60 s sample grid
phase0/checkpoints.csv                exact minute-aligned replay checkpoints
phase0/probe_manifest.csv             single-actuator D2 setting probes
phase0/d2/*.json/*.npz/*.csv.gz       code-bound D2 authoritative branches
phase0/d2/RUN_SUMMARY.csv
phase0/timescale_detail.csv
phase0/timescale_summary.json
phase0/d3/...                         optional pulse/release sequences for recovery/decay
```

Phase-0 data is timing evidence only. If its sample step differs from the frozen production model step, it is forbidden from production Step2 shards.


Formal fixed strategies:

```text

```

Resume is allowed only when the V2 baseline sidecar verifies current code hash, source/event INP, physical hash, strategy, frozen timing, SWMM process/thread contract and hashes of all generated artifacts.

## 5. Step1 data

Step1 reconstructs the current full hydraulic state from causal sparse history.

Fresh sources:

```text
baseline_cache/STEP1_BASELINE_INDEX.csv
```

plus optional development/train-only D1 exploration:

```text
d1/D1_RUN_INDEX.csv
d1/<event>/*.json
d1/<event>/*.compact.npz
d1/<event>/*.node_statistics.csv.gz
d1/<event>/*.decisions.jsonl
```

D1 is for Step1 state-space coverage only. It is not a D2/D3 checkpoint source.

Step1 model evidence:

```text
models/step1.pt
models/step1.pt.json
models/step1.pt.trainstate.pt          resumable epoch state
acceptance/step1_metrics.json          rainfall-group-balanced validation metrics
acceptance/step1_gate.json             preregistered source-bound gate
```

The train-state can resume only for the exact same run-index, graph, sensors, time contract, architecture, hyperparameters and source tree.

## 6. Production D2 data

Purpose: learn/verify same-prefix local actuator effects over the frozen production time grid.

Canonical inputs:

```text
baseline_cache/NO_CONTROL_D0_INDEX.csv
checkpoints/checkpoint_settings.csv
```

Generated data:

```text
d2/probe_manifest.csv
d2/RUN_SUMMARY.csv
d2/<branch>.json
d2/<branch>.compact.npz
d2/<branch>.node_statistics.csv.gz
```

Each D2 branch binds:

- event/rainfall/split;
- exact replay checkpoint;
- candidate action SHA;
- source/runtime INP hashes;
- horizon and sample step;
- current source-tree SHA;
- compact/statistics hashes.

## 7. Production D3 data

Purpose: teach and validate multi-actuator, multi-step interaction effects—the action space actually searched by MPC.

```text
d3/sequence_manifest.csv
d3/D3_RUN_SUMMARY.csv
d3/<branch>.json
d3/<branch>.compact.npz
d3/<branch>.node_statistics.csv.gz
```

D3 sequence resume binds sequence SHA, checkpoint, event, time grid, controls-disabled runtime and current code.

## 8. Step2 index and time-locked shards

Build one D2+D3 run index, then separate train/validation shards by rainfall-group-disjoint development fold:

```text
step2/step2_run_index.csv
step2/train_shards/manifest.json
step2/train_shards/step2_*.npz
step2/validation_shards/manifest.json
step2/validation_shards/step2_*.npz
```

A shard manifest contains one and only one:

```text
model_step_seconds
horizon_steps
```

Phase-0 60 s branches and production 300 s branches cannot be mixed.

Step2 model evidence:

```text
models/step2.pt
models/step2.pt.json
models/step2.pt.trainstate.pt
acceptance/step2_metrics.json
acceptance/step2_gate.json
```

Step2 training supervises:

1. future hydraulic state trajectory;
2. actuator flow trajectory;
3. exact cumulative SWMM node flooding volume.

Predicted cumulative volume uses the same current+future trapezoidal operator used by MPC/validation/gradient/ranking.

## 9. Action-effect acceptance evidence

Local D2 finite-difference gradient evidence:

```text
acceptance/gradient_detail.csv
acceptance/gradient_metrics.json
acceptance/gradient_gate.json
```

Joint action ranking evidence:


D2 validates local/boundary single-actuator response; D3 validates joint multi-actuator multi-step sequence ordering and selected-action regret.

Formal statistics are equal-weight per independent rainfall group.

## 10. Proposed development closed-loop evidence

```text

                         *.compact.npz
                         *.node_statistics.csv.gz
                         *.decisions.jsonl
development/RUN_INDEX.csv
```

## 11. Policy Lock

Required output:

```text
policy_lock/policy_lock.json
```

Contract:

```text
WUHAN_RTC_TFV_FIRST_POLICY_LOCK_V4_CODE_TIME_DATA_BOUND
```

It binds source code, physical model, priority/sensor mapping, rainfall split, controller timing, model time contracts, model hashes/training lineage, acceptance contracts, runtime evidence and baseline plan.

Any source-code change after Policy Lock invalidates Final generation/compilation.

## 12. Untouched Final evidence

Fixed Final comparators are generated once using the locked configuration:

```text
final_baseline_cache/FINAL_BASELINE_RUN_INDEX.csv
```

Proposed Final runs and all fixed references must have one code-bound Formal manifest per event/strategy:

```text
<run>.formal_manifest.json
<run>.formal_manifest.peak_replay.json
```

Peak replay uses isolated temporary SWMM `.rpt/.out` files and deletes them after successful replay.

Final compiler outputs:

```text
final/formal_final_detail.csv
final/formal_final_group_detail.csv
final/formal_final_summary.csv
final/proposed_vs_no_control.csv
final/proposed_vs_internal_rtc.csv
final/proposed_vs_all_open.csv
final/proposed_vs_all_closed.csv
```

Final summary first collapses variants inside each independent rainfall group, then gives every rainfall group equal statistical weight.

## 13. What must never be reused

Do not import into the v0.6 Fresh Workspace:

- Project6 hydraulic trajectories;
- old baseline outcomes without V2 code-bound sidecars;
- old D1/D2/D3 branches without generation keys/current code hash;
- old Step1/Step2 checkpoints without `RTC_TORCH_CHECKPOINT_V2_CODE_BOUND`;
- old Phase-0 data as production Step2 data when the time grid differs;
- old acceptance JSON generated by a different source tree;
- old Policy Locks or Final evidence.

## 14. Safe resume rule

A computation is reusable only when its declared generation/training key and every required artifact hash still validate under the current source tree. File existence alone is never sufficient evidence for resume.
